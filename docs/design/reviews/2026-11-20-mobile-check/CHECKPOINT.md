Chromium and Firefox exercised Home, assistant settings, a populated chat and the shared library at seven sizes from 320 × 568 to 1366 × 768, including a short 390 × 440 window. The final runs checked the first shared file was reachable, that keyboard focus returned to the settings opener, and that the current reading position survived navigation. An independent visual review checked the screenshots in light and dark.

On an iPhone 13 Pro simulator running Safari on iOS 18.2, one participant sent a group message and an addressed question in each orientation with the system keyboard open. The second session received each of the four messages exactly once without a refresh. The database recorded assistant addressing only on the two explicit questions. [Safari captures and device limits](safari/README.md).

The local browser release check also exercised an update arriving during an unsent message with an attachment. The draft survived deferring the update. Two separate sessions changed the Goal and archived or restored a topic, then checked the resulting chat entries. The tests used a disposable workspace and synthetic accounts.

The local production build also excludes root-level PDF files from its API dependency manifests. After the change, none of the 28 generated manifests referenced a root PDF. The Docker build already excludes these files from its input.

Final verification: 566 automated checks passed across 76 Vitest files with local PostgreSQL and test provider boundaries. TypeScript, formatting, backend compilation and the production Web build passed. ESLint reported one warning in an earlier design prototype. Next reported two dynamic file-tracing warnings in audio and document processing. Browser and Safari results above are separate from the Vitest count.
