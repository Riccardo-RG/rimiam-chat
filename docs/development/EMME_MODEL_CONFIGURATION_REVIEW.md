# Emme's response time and model settings

Design review, 20 November 2026. The initial design is retained below. The local Web app now implements the Home panel, per-space and personal conversation selection, creator summary, configurable name and downloadable operating instructions. [Approved scope](../decisions/ADR-0017-connessione-assistente-per-spazio.md) · [Adapter contract and current limits](ASSISTANT_CONNECTIONS.md). The [deployment record](RAILWAY_DEPLOYMENT.md) tracks production evidence.

## Where a reply spends time

A shared message is saved before its interpretation runs. Two worker slots serve several capabilities. Conversation turns preserve their order within a Workspace, so earlier work can delay an explicit question. Once a turn starts, the model may request more relevant sources. The default allows up to four sequential rounds and a sufficient first answer needs just one. The server validates the complete structured result before publishing. The Web client then refreshes its view when it receives a journal update. Both the worker's fallback poll and the journal scan have a one-second interval. Neither interval establishes how long a particular message waited. [Message command](../../src/server/commands.ts) · [Worker](../../src/server/worker-runner.ts) · [Interpretation](../../src/server/interpretation.ts) · [Journal delivery](../../src/app/api/workspaces/%5Bid%5D/events/route.ts)

Measure four intervals separately for explicit requests: message saved to work started, each provider round, final result to reply saved, and reply saved to visible text. Compare median and 95th percentile with sample sizes, failures and round counts. Existing shared usage records time each provider attempt and store its model and outcome. They lack a turn identifier and cannot measure browser delivery. Keep diagnostics aggregate and content-free. If provider time dominates, compare two compatible models on identical synthetic conversations, checking evidence use, appropriate silence, latency and cost. If queueing dominates, investigate earlier work first. [Usage records](../../migrations/035_shared_ai_usage.sql) · [Turn history](../../migrations/014_conversational_miriam.sql)

**Observed 20 November.** One content-free production read selected successful `interpret` jobs from the current worker deployment within the previous seven days. Its 31 matching completions had a median duration of 3.85 s and a 95th percentile of 6.93 s. This deployment started on 19 November. Earlier deployments, time in the queue, client display, and failed attempts fall outside the sample. An interpretation can finish without publishing a reply. These numbers do not isolate a particular model or measure the latency that a person experienced. The private database was inaccessible with the release credential, so no per-model production percentile is available for this review.

## One Home entry for configuration

- **Model.** A discreet “Configura Emme” entry beside “Tu ed Emme” could show the active provider, model, scope and payer. Start with the deployment default and administrator-approved models that pass the structured-output contract. The existing adapters support OpenAI, Anthropic and Ollama via server configuration. The connection test should disclose any cost and use synthetic input. Provider credentials belong on the server, masked in the UI and revocable. [Provider adapters](../../src/server/structured-llm.ts)
- **Instructions.** Offer a downloadable English Markdown file showing the baseline guidance and the effective preferences for the selected scope. Allow edits to preferences such as tone, language or answer length, with preview, version history and restore. Keep source access, output validation, consent and Commit Points enforced by server code. Exclude credentials, conversations and private context from the export. [Conversation guidance](../../src/server/miriam-prompt.ts) · [Specialist guidance](../../src/server/analysis-specialist.ts)
- **Name.** Keep Emme as the default and let a scoped display name appear in labels, explicit mentions and prompts. Preserve the stable AI actor and original messages when a name changes. Store the addressed actor when sending so a delayed turn, a rename or a human namesake cannot redirect a request. If a name matches more than one actor, let the sender select the person or AI. [Current aliases](../../src/shared/miriam-address.ts) · [Existing human-name resolution](../../src/server/participation.ts)

For the hosted beta, start with operator-managed shared credentials. A private preference applies only to the person's own assistant. Before enabling member-configurable shared providers, decide **who can authorize sending the group's context to that provider and whose account pays**. Workspace membership alone supplies neither authorization. Show the recipient before a change, never silently switch provider after failure, and record the effective configuration revision for future runs. Existing history and authority stay attached to the Workspace. [Product identity and collaboration policy](../product/MVP_SPEC_v0.1.md#7-emme-identità-presenza-e-collaborazione)

## Founder brief and integration options

On 20 November Riccardo specified one Home panel supporting local and hosted models **and independently built agents**, a customizable assistant name, and visible, downloadable, editable initial instructions. This describes the product direction. The running beta still takes its model from server configuration. Current prompt fragments and generated schemas live in code. There is no universal agent connector or live settings editor.

1. **Connection.** Show where processing runs, the model or agent, which space uses it and what data leaves RIMIAM. A model supplies structured responses. A separately operated agent may have its own memory, tools and credentials. Start with one documented request/response adapter for contributed answers with validated source handles. A connector may advertise broader capabilities later. A URL alone cannot establish compatibility. A self-hosted installation can reach a local model on its own network. In Railway, localhost points to Railway. Reaching a model on the founder’s computer requires a deliberately authorized private connection or running the app with the model locally. Keep secrets and endpoint administration out of the browser. An agent that can independently send mail or make purchases needs a restricted, read-only configuration before it receives real chat context. RIMIAM cannot undo actions an outside service takes with its own credentials. A2A’s Agent Card and declared capabilities are an interoperability reference for a later adapter. [Current inference contract](../../src/server/structured-llm.ts) · [A2A specification](https://a2a-protocol.org/latest/specification/)
2. **Instructions.** In the panel show the actual instruction documents used for a turn, in application order, with author, version and scope. Read, edit, preview differences, test against a synthetic conversation, publish a version, download Markdown, or restore the prior version. Start by extracting the existing English guidance into the same source used for display and execution. Display separate notes for runtime context and the enforced response contract. Keep credentials and private Workspace material out of general downloads. A run records the exact instruction and connection revisions it used, even if someone edits during execution. Let advanced users change operating guidance. Permission to read a source, disclose a recording, or act for a person must continue to be checked independently by server code.
3. **Identity and permissions.** Preserve one recognizable chat participant when the connection changes. A name change affects display and future addressing. Historical authors and receipts stay attributable. For the hosted beta the recommendation is an installation operator who registers destinations and credentials, with shared selection limited to destinations approved for that space. The founder subsequently assigned shared conversation selection to the eligible creator. Changing the installation’s billing account remains an operator responsibility. Let members see the effective configuration before a request. Test reachability and compatibility with synthetic content and show the provider before a paid live check.

## What to simplify first

| Observation in the current Web app | Engineering recommendation | Evidence for success |
| --- | --- | --- |
| Shared attachments already use one ordered draft with permission and receipt handling. The separate document library and camera are entry points to the same files. | Keep one sending path. Add input methods at the boundary. Keep optional model reading visibly opt-in. | Two people see the same single post and can return to it from Media. Cancelling the picker preserves the draft. |
| The main Web page coordinates the rail, workspace lifecycle, draft recovery, timeline and tool panels in one component. | On the next change to the composer, extract its view and typed actions while keeping the existing send journal and draft ownership. On the next panel change, separate the shared Goal editor from mandates and governed acts. No general frontend rewrite is needed. | The same two-member journeys work after reload, during a stale edit and on a narrow touch viewport. |
| There are already a Conversation interpreter, a research path and an analysis Specialist. Adding one visible bot per connector would expose routing and duplicate permission checks. | Keep the assistant’s identity and Workspace history stable. Add a connector at execution time and return a Contribution. An external agent can request a governed action through the same human controls. | Switching connections preserves a conversation and its sources. Invalid citations, cross-space reads and actions outside the contract fail closed. |
| The current worker sample combines queue-independent interpretation time with provider work and multiple rounds. | Measure elapsed time per step before changing models or raising concurrency. Give the requester immediate, truthful feedback when their request is saved and when the worker starts. | Compare the same conversations, useful answers and end-to-end latency with the same budget. |

Recommended sequence: **read/export effective guidance → versioned edits with preview and rollback → connection selection and synthetic compatibility checks → one independently operated agent in a test workspace**. Test a lost response, a provider switch during a job, an unsupported feature, missing connectivity and withdrawal of access. Each increment should be useful by itself.
