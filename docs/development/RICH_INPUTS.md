# Documents, images and voice

Implemented 2026-09-11; capture/playback and portable parser setup completed 2026-09-12. Uploads are sources, never Accepted Information or authority. [Sources](../../src/server/sources.ts), [extraction worker](../../src/server/media-worker.ts), [provider boundary](../../src/server/media-provider.ts), [migration 019](../../migrations/019_rich_source_ingestion.sql) and [immutable processing history](../../migrations/021_document_processing_history.sql).

## Supported path

Web, iOS and Android use the same `document.upload` command: filename, exact base64 bytes, optional previous source identity, and explicit `allowModelProcessing: true` for image/audio processing. Supported originals: UTF-8 TXT/MD/CSV, PDF, DOCX, PNG/JPEG/WebP and MP3/M4A/WAV/WebM/OGG. Binary uploads are bounded at 8 MiB; extracted text at 200,000 characters. UTF-8 files retain the existing 1 MiB input bound. Bounds reject oversized input visibly; no silent truncation. All three clients record voice locally and require explicit sharing/model disclosure. Capture stops on background/unmount; selecting another file resets disclosure consent. Microphone permission and, on web, a secure browser context are necessary.

Miriam messages offer explicit device-voice playback of their exact visible text. Web selects only `localService` voices; Android excludes network-required voices; iOS uses installed system voices. Missing device voices produce a limitation, not an online fallback. Playback stops on leaving the relevant surface/backgrounding. This is presentation, not new AI output, a retained source, consent, or authority. **Refined 2026-09-13:** [ADR-0015](../decisions/ADR-0015-voce-chiamate-consenso-registrazione.md) adds Conversation voice/dialogue and human audio calls; [VOICE_CALLS](VOICE_CALLS.md) defines their implemented source/consent boundary. Video calls remain excluded. Physical microphone, audio routing and installed-voice behavior require device acceptance; compilation does not prove those experiences.

The original bytes, hash, contributor, document identity/version and qualification are immutable. Download through the authorized common `GET /api/v1/workspaces/{id}/source-file?id={sourceId}` works before extraction. A queued/failed source has no invented textual content and is excluded from the context-source view until a validated extraction is published. Original and extraction hashes are distinct. Successful extraction preserves qualifications, parser/model provenance and original identity, then enters the existing unaccepted source/interpretation pipeline. Voice contribution does not establish the speaker's identity, consent or authority.

## Local parsing and optional model configuration

PDF/DOCX parsing runs [a bounded subprocess](../../scripts/extract-document.py), using pinned `pypdf` and `python-docx` libraries in [requirements-documents.txt](../../requirements-documents.txt). Create an ordinary Python virtual environment, install that file and set `DOCUMENT_PYTHON_PATH` to its Python executable; see [README](../../README.md#local-document-parsers). An existing developer-specific Python path is not portable packaging. No application secrets are passed to the parser. External relationships, PDF actions, macros and embedded programs are not executed. Password-protected, scanned/textless, oversized or unreadable files yield an explicit limitation; image/layout/annotation fidelity may require inspecting the original. No OCR result is fabricated.

Image interpretation uses the existing `AI_MODE=anthropic`, `ANTHROPIC_API_KEY`, `AI_MODEL` configuration. Voice uses `TRANSCRIPTION_PROVIDER=openai`, `OPENAI_API_KEY`, and an explicitly selected `TRANSCRIPTION_MODEL`. They receive only the deliberately disclosed original file, not other Workspace/mailbox content. Provider output remains untrusted and validated. No configured provider produces `needs_configuration`; missing consent produces `needs_input`. Adding credentials never implies consent for previously undisclosed media. A retry is a new explicit act through `document.retry`, requiring fresh `allowModelProcessing: true` for media; it does not automatically repeat a consequential action.

## Durability and verification

Graphile carries only source IDs. A short transaction validates active contributor/account and membership version and claims an extraction attempt; parsing/inference runs outside Workspace locks. Publication rechecks eligibility and the exact attempt fence. Interrupted leases can be recovered, but late output cannot replace a newer attempt. Ended and re-entered membership does not revive the previous claim. Immutable attempts/results and processing events retain provenance, failure codes, retry authors and recovery history; only the current valid published result enters retrieval. No acceptance, commitment, representation or external effect follows from extraction.

[Targeted tests](../../tests/media.test.ts) use genuine PDF/DOCX fixtures with local maintained parsers, isolated PostgreSQL, and deterministic model/HTTP doubles for disclosure, privacy/isolation, ended eligibility, retries, late results, immutable originals and qualifications. They do not certify real transcription/vision quality. Live image/voice verification remains pending credentials, explicitly disclosed controlled inputs and review of transcription errors/uncertainty; test both the original and the derived result. Files remain in PostgreSQL for this bounded path; a future object-store migration must preserve identities/hashes/references.

Primary references: [pypdf extraction](https://pypdf.readthedocs.io/en/stable/user/extract-text.html), [python-docx](https://python-docx.readthedocs.io/en/latest/), [OpenAI transcription API](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create). These adapters and configurable operational bounds are implementation choices, not new domain decisions.
