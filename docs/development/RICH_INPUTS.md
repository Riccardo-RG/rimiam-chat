# Documents, images and voice

Implemented 2026-09-11; capture/playback and portable parser setup completed 2026-09-12. Uploads are sources, never Accepted Information or authority. [Sources](../../src/server/sources.ts), [extraction worker](../../src/server/media-worker.ts), [provider boundary](../../src/server/media-provider.ts), [migration 019](../../migrations/019_rich_source_ingestion.sql) and [immutable processing history](../../migrations/021_document_processing_history.sql).

## Supported path

Web, iOS and Android use the same `document.upload` command: filename, exact base64 bytes, optional previous source identity, and explicit `allowModelProcessing: true` for image/audio processing. Supported originals: UTF-8 TXT/MD/CSV, PDF, DOCX, PNG/JPEG/WebP and MP3/M4A/WAV/WebM/OGG. Binary uploads are bounded at 8 MiB; extracted text at 200,000 characters. UTF-8 files retain the existing 1 MiB input bound. Bounds reject oversized input visibly; no silent truncation. All three clients record voice locally and require explicit sharing/model disclosure. Capture stops on background/unmount; selecting another file resets disclosure consent. Microphone permission and, on web, a secure browser context are necessary.

On Web, users can listen to the exact text of Emme’s messages. The browser uses a `localService` voice and stops playback when the user leaves the relevant view or backgrounds the page. In the mobile app, Emme’s replies appear as text and users can listen to original audio messages. [ADR-0015](../decisions/ADR-0015-voce-chiamate-consenso-registrazione.md) covers voice dialogue and human audio calls. [VOICE_CALLS](VOICE_CALLS.md) describes recording consent and how transcripts link to their sources. Physical microphone, audio routing and browser voice availability require testing on devices.

The original bytes, hash, contributor, document identity/version and qualification are immutable. Download through the authorized common `GET /api/v1/workspaces/{id}/source-file?id={sourceId}` works before extraction. A queued/failed source has no invented textual content and is excluded from the context-source view until a validated extraction is published. Original and extraction hashes are distinct. Successful extraction preserves qualifications, parser/model provenance and original identity, then enters the existing unaccepted source/interpretation pipeline. Voice contribution does not establish the speaker's identity, consent or authority.

## Local parsing and optional model configuration

PDF/DOCX parsing runs [a bounded subprocess](../../scripts/extract-document.py), using pinned `pypdf` and `python-docx` libraries in [requirements-documents.txt](../../requirements-documents.txt). Create an ordinary Python virtual environment, install that file and set `DOCUMENT_PYTHON_PATH` to its Python executable; see [README](../../README.md#local-document-parsers). An existing developer-specific Python path is not portable packaging. No application secrets are passed to the parser. External relationships, PDF actions, macros and embedded programs are not executed. Password-protected, scanned/textless, oversized or unreadable files yield an explicit limitation; image/layout/annotation fidelity may require inspecting the original. No OCR result is fabricated.

Image interpretation uses the selected vision-capable `AI_MODE=openai` + `OPENAI_API_KEY` + `AI_MODEL` (preferred), or the optional Anthropic adapter. Voice uses `TRANSCRIPTION_PROVIDER=openai`, the same server-only `OPENAI_API_KEY`, and an explicitly selected `TRANSCRIPTION_MODEL`. They receive only the deliberately disclosed original file, not other Workspace/mailbox content. Provider output remains untrusted and validated. No configured provider produces `needs_configuration`; missing consent produces `needs_input`. Adding credentials never implies consent for previously undisclosed media. A retry is a new explicit act through `document.retry`, requiring fresh `allowModelProcessing: true` for media; it does not automatically repeat a consequential action.

## Durability and verification

Graphile carries only source IDs. A short transaction validates active contributor/account and membership version and claims an extraction attempt; parsing/inference runs outside Workspace locks. Publication rechecks eligibility and the exact attempt fence. Interrupted leases can be recovered, but late output cannot replace a newer attempt. Ended and re-entered membership does not revive the previous claim. Immutable attempts/results and processing events retain provenance, failure codes, retry authors and recovery history; only the current valid published result enters retrieval. No acceptance, commitment, representation or external effect follows from extraction.

[Targeted tests](../../tests/media.test.ts) use genuine PDF/DOCX fixtures with local maintained parsers, isolated PostgreSQL, and deterministic model/HTTP doubles for disclosure, privacy/isolation, ended eligibility, retries, late results, immutable originals and qualifications. They do not certify real transcription/vision quality. Live image/voice verification remains pending credentials, explicitly disclosed controlled inputs and review of transcription errors/uncertainty; test both the original and the derived result. Files remain in PostgreSQL for this bounded path; a future object-store migration must preserve identities/hashes/references.

Primary references: [pypdf extraction](https://pypdf.readthedocs.io/en/stable/user/extract-text.html), [python-docx](https://python-docx.readthedocs.io/en/latest/), [OpenAI transcription API](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create). These adapters and configurable operational bounds are implementation choices, not new domain decisions.

## Preview before download

Opening a shared attachment in a Workspace message, the private two-person chat or Condivisi shows its name, type and size before the user chooses to download or export the original. The same authorized file endpoint serves `view=preview`. Workspace membership, source withdrawal and direct-chat participation are checked for each request. A private attachment stays in its direct chat. Closing the Condivisi preview preserves the current filter and position. “Vai al messaggio” opens its original post.

Image previews use the authorized original. TXT, Markdown, CSV and DOCX are displayed as plain text with a bounded excerpt. For a PDF the app renders only the first page on demand with local Poppler (`poppler-utils` on Debian, included in the production image). Without a usable rendered page it tries local text extraction. Unsupported or unreadable files show metadata and an explicit download action. Preview does not call an AI provider or change Context.

A Web process runs at most one preview parser at a time. PDF rendering accepts at most 8 MiB, renders the first page at up to 1,000 pixels and caps output at 1 MiB. The subprocess receives only document bytes, with 4 seconds of CPU, a 6.5-second wall deadline and a 256 MiB address-space limit on Linux. Disconnects terminate the parser. This on-demand path does not enqueue extraction or reprocess files in the list.

For a shared MP3, M4A, WAV, WebM or OGG, use the preview’s play button to start local playback. The Web player requests authorized byte ranges. The Flutter player requests `view=audio` after the tap and gives the decoder a temporary app file. Leaving the preview or backgrounding the app stops playback. The iPhone 13 Pro simulator on iOS 18.2 played and stopped a nine-second synthetic WAV. Support for the other formats depends on the device codec. Physical speaker and headphone routing require device tests.

In **Condivisi**, the file preview shows its format and size. A busy preview offers a retry that only reloads the preview. If content extraction failed or needs consent, a contributing member can request reading separately. An image or audio retry names the file, asks whether to send it to the configured AI service and rechecks access and the retained version before sending the command. Cancelling leaves the preview open. The [Flutter attachment tests](../../mobile/test/attachments_test.dart) and [collection tests](../../mobile/test/file_library_test.dart) also cover stopping a pending download, cancelling AI consent and a permission change between preview and confirmation.

## Draw in a workspace conversation

Type `/h` or select **Draw** from the actions in a group chat. Draw with a mouse, finger or stylus, change pen color or undo the last stroke. **Add to message** renders a PNG into the current draft. The author can remove it, add a caption or send it through the usual attachment flow. Other members receive it only after Send. The attached image survives a reload or relaunch with the draft. Closing the drawing surface before attaching discards the sketch. No image-generation provider is involved.

The [shared geometry](../../src/shared/chat-sketch.ts) preserves the page across rotation. [Web](../../src/client/chat-sketch.tsx) and [native](../../mobile/lib/chat_sketch.dart) use their own input and PNG renderers. The [two-member regression](../../tests/e2e/chat-sketch.spec.ts) draws real strokes and checks the received pixels.
