# Voice and Workspace audio calls

Implementation boundary, 2026-09-13. Product approval: [ADR-0015](../decisions/ADR-0015-voce-chiamate-consenso-registrazione.md). Current verification/closure: [STATUS](STATUS.md). Activation checklist: [DEPLOY_EXTERNAL_SERVICES](DEPLOY_EXTERNAL_SERVICES.md).

## Entry points and behavior

- [Voice command/read](../../src/server/voice.ts), [voice contract](../../src/contracts/voice.ts), [migration 025](../../migrations/025_conversation_voice.sql): `voice.send` binds an immutable human Conversation message to its original source and `message`/`miriam` intent. Existing [media ingestion](RICH_INPUTS.md) transcribes with explicit disclosure. Transcript and original remain separate. Voice-addressed turns use the existing Context/interpreter and return ordinary source-linked Miriam messages. Recent voice transcripts participate in conversational continuity; no new chat memory is introduced.
- Device recording plus silence-delimited turns → real transcription → existing conversational model → exact device TTS. Start/end remain explicit; background suspends the AI voice dialogue. Natural bounded web-search requests prepare a visible query; `research.request` owns actual disclosure. Analysis uses the existing Active Work suggestion/control boundary. No spoken content directly authorizes an external action.
- [Call commands](../../src/server/calls.ts), [contract](../../src/contracts/calls.ts), [transport](../../src/server/call-provider.ts), [control/recovery](../../src/server/call-worker.ts), [transcript/storage](../../src/server/call-transcripts.ts), migrations [026](../../migrations/026_workspace_audio_calls.sql)/[027](../../migrations/027_call_recording_source.sql)/[028](../../migrations/028_call_reconciliation_schedule.sql)/[029](../../migrations/029_call_consent_provenance.sql). PostgreSQL owns participation, consent epochs/history, recording intents/results and analysis requests. LiveKit carries only audio transport; only opaque admitted participant identities receive microphone-only tokens. No room administration, recording privilege, video, data publishing or AI agent is granted to a client.
- `GET voice`, `GET calls`, `POST call-connect`, `GET call-audio?id=…` sit under the existing authenticated `/api/v1/workspaces/{id}/` boundary. Commands/receipts use the existing journals. Audio downloads are authenticated, private and support ranges for recordings. Native clients preserve origin-bound credentials and do not follow credential-bearing redirects.

## Recording and recovery

The server requires all admitted participants’ personal consent to the exact history/retention/transcription notice for the current request epoch. New arrivals receive no token until ongoing capture is stopped or technically fenced; no one consents for anyone else. Egress captures individually authorized microphone track IDs, never room-wide audio. A new interval preserves its participant, epoch, source track, storage key and an immutable reference to the exact personal consent event; historical notice and epoch are inspectable.

Withdrawal disconnects the withdrawing participant’s local audio immediately before the authenticated act; the server ends and revokes that transport identity. The person can rejoin the continuing call through a fresh, initially unconsented identity after the capture barrier. This conservative re-entry is explicit in all clients. The server records a stop intent and reconciles Egress; the UI does not claim confirmed termination while a transport outcome is unknown. Network operations cannot be represented as physically instantaneous acknowledgements. If capture cannot be confirmed stopped, provider removal/revocation fences the affected track; re-entry requires a fresh admitted identity and consent. Other participants may continue the unrecorded call. Leaving retains prior consent history/material and does not invalidate other participants’ consent. Heartbeat/eligibility checks revoke abandoned or ineligible transport participation; SDK reconnect does not establish new membership.

External start intents are durable before dispatch. Unknown starts are reconciled by exact output identity, never blindly restarted. Orphan transport activity is stopped, never adopted as consent provenance. A crash before dispatch leaves a non-submitted interval and requires a fresh request. Unknown historical output can remain visibly unresolved after subsequent capture is fenced; do not invent a recording or erase its history. Inspect LiveKit’s exact Egress/output evidence before resolving operational failures. Normal transport control has a short independent recovery loop; transcription/model jobs do not occupy that control path.

Completed audio is pinned to its S3 VersionId, length and SHA-256 before transcription; overwrite of the current object cannot replace the historical source. FFmpeg creates bounded audio segments for the real transcription adapter. Published transcript segments are immutable, individually hashed/qualified and survive restart; fenced attempts cannot overwrite newer work. Failed/configuration-required transcription is explicitly retryable. Temporary files are removed, not authoritative originals.

Raw call transcripts are stored outside `workspace_source`: recording consent does not trigger Context interpretation or analysis. A separate eligible contributor’s `call.analyze` after the call and completed transcription registers the exact request, exposes source-linked segments and starts/reuses bounded Active Work. Explicit identities narrow source selection; `needsMore` can expand relevant context. No full transcript is appended to every future inference. The result remains an unadopted Contribution; existing capability commands own any adoption, Task, Commitment or external effect.

## Clients and verification boundary

[Web voice](../../src/client/conversation-voice.tsx)/[calls](../../src/client/workspace-call.tsx), [SwiftUI media](../../mobile/ios/Miriam/WorkspaceMedia.swift), [Compose media](../../mobile/android/app/src/main/java/it/miriam/nativeapp/WorkspaceMedia.kt) and [views](../../mobile/android/app/src/main/java/it/miriam/nativeapp/WorkspaceMediaViews.kt) expose the same consent/control/history boundary. Human calls exclude local AI TTS/other microphone capture. iOS uses background audio; Android uses a visible microphone foreground service with an explicit leave action. Returning to the app reloads durable history; a new process does not silently rejoin a call or consent again.

Targeted [voice/call tests](../../tests/voice-calls.test.ts) exercise real PostgreSQL, real FFmpeg and test-only provider boundaries. Existing media/Conversation/API tests remain applicable. Tests cannot certify live Egress behavior, microphone routing, acoustic echo, transcript quality, network handoff or phone background behavior. Those checks require configured services, explicit recording consents and physical devices; record actual results before release. No provider activation or browser/manual-call pass is implied by compilation.
