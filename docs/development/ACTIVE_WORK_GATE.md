# Active Work — implementation gate

**2026-09-10.** Derived from approved [ADR-0014 v2](../decisions/ADR-0014-active-work-specialist-contribution.md), with prior ADRs unchanged. This compact engineering gate defines the bounded BUILD explicitly authorized by the user on 2026-09-10; it is not another normative decision. Implementation/navigation: [ACTIVE_WORK](ACTIVE_WORK.md). Current implementation: [STATUS](STATUS.md); entry points: [CODEMAP](CODEMAP.md).

## Authorized bounded BUILD

Durable shared-context analysis/brief, requested conversationally or initiated from bounded relevant Workspace intent/state, using already-shared material and one bounded analysis Specialist capability. Include continuing compatible existing work, inspectable Contributions, state awareness and shared conversational controls on web, iOS and Android. No mandatory Task, Goal/Workstream hierarchy or human assignment. A result may remain unadopted; any supported adoption/handoff must use its governed capability without broadening that capability.

## Reuse, with limits

- [Commands/receipts](../../src/server/commands.ts), [Workspace guards](../../src/server/workspace-state.ts), common API/contracts, sync and client journals listed in CODEMAP.
- [Worker registry/recovery](../../src/server/worker-runner.ts), [research attempts](../../src/server/research.ts) and [follow-up recovery](../../src/server/tasks-worker.ts) as bounded infrastructure patterns. Do not inherit research requester-only control, a human identity for autonomous work or global context-revision equality as the complete Active Work validity rule.
- [Interpretation/source retrieval](../../src/server/interpretation.ts), [Task context](../../src/server/tasks-context.ts) and existing provider seams, with operation/Capability Contract checks. Existing source-triggered candidate publication is not a general Contribution publication API.
- [Artifact governance](../../src/server/artifacts.ts) and existing Task/Calendar/Email commands remain the adoption/effect boundaries. Current Artifact compilation is restricted to selected question/information/source references; do not bypass it by labelling arbitrary AI output an adopted Artifact.

## Mandatory verification

- Domain/authority/isolation: negative cross-member/Workspace/private-context cases, ended eligibility/access, non-contributor controls and no indirect normative effects or borrowed permissions.
- Lifecycle/concurrency: compatible incorporation, conflicting members, stale controls/results, anchors, pause/stop/resume, restart recovery, duplicate jobs/commands, parallel works, overlap preference and no automatic restart after completion.
- Provenance/context: immutable history, exact input/contract versions, older selective retrieval, insufficient context, Specialist overreach, malformed output/invalid citations and unadopted results.
- Capability/UI boundaries: unchanged approval scope/version/Commit Points; meaningful Conversation presence and equivalent controls across web/iOS/Android, reconnect/relaunch and command-response loss.
- Follow AGENTS testing cadence: targeted feedback/regressions first; milestone checks include lint/typecheck/formatting, applicable migrations on fresh/existing databases, real worker persistence/recovery and all-client scenarios. Provider doubles are deterministic and test-only; real-model quality/service verification stays pending without credentials.

## First-BUILD non-goals and critical pass

No private mailbox/calendar ingestion, autonomous external query disclosure or external writes, WIRE, service activation, push, new mandates/protected governance, expanded Artifact lifecycle, agent marketplace, generic actor hierarchy, workflow/tool engine, vector database or prescribed deduplication algorithm. Existing exact-query research can remain separate; retained shared evidence is usable without adding provider calls.

Critical pass: the boundary preserves independent capability authority, excludes undisclosed private inputs, retains immutable evidence, and does not reduce shared conflict handling to optimistic locking. One Specialist capability needs neither a product entity per invocation nor a generic framework. Existing current-state guards require adaptation, not weaker authorization. No remaining contradiction blocks approval of ADR-0014; **The subsequent explicit user authorization covers this bounded BUILD only; no WIRE or next increment is authorized**.
