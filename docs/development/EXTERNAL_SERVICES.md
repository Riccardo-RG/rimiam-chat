## Structured model configuration and recovery

[The shared structured-model boundary](../../src/server/structured-llm.ts) now supports OpenAI (preferred) and Anthropic through AI SDK, or Ollama's native `/api/chat`, not its OpenAI-compatible endpoint. Ollama receives the Zod-derived JSON schema and validates the complete returned object; partial, malformed, truncated or nonconforming output is rejected. A trusted endpoint is configured server-side; redirects and credentials in its URL are rejected. No endpoint, model or credential has been activated by this update. Configuration presence is not a liveness or quality check.

Configuration missing/rejected, rate limit, timeout, unavailable transport, rejected request and invalid output have distinct safe codes; provider bodies, raw error messages and SDK causes do not enter user-facing errors or worker delivery logs. An interpretation records failure against its current generation; late failure cannot overwrite or signal failure for recovered current work. Active Work preserves the same distinctions behind its existing contract/access/control fences. Web/iOS/Android show readable explanations and retain explicit retry/resume paths. [Adapter checks](../../tests/structured-llm.test.ts) use isolated doubles and no real provider; live behavior is unverified. Ollama does not activate the separate image/transcription adapters.

## Account-delivery activation details

Apply migrations 005–006 and run the worker before hosted registration/recovery. The outbox stores account-security delivery state outside Workspace history; job payloads contain a delivery ID, not a bearer URL. Links are encrypted with AES-GCM and a domain-separated key derived from `BETTER_AUTH_SECRET`; ciphertext is bound to record ID, purpose and recipient. Sender payloads cannot change on retry. Existing local development inbox links remain plaintext by design and must never be exposed as a hosted mailbox.

Automatic attempts are limited to the same recipient/content and a one-hour delivery lifetime, within the selected transport's idempotency window. Unknown acknowledgements are not delivery receipts. Expired links require a new user request; five exhausted automatic attempts are not an indefinite resend loop. Retry counts/leases/TTL are operational settings, not Workspace governance. Monitor queued/unknown/configuration/expiry states during activation. Rotating the auth secret makes pending ciphertext unreadable; users must request fresh links. Key rotation/versioning beyond that conservative behavior and provider delivery/bounce monitoring remain operational work.

This account-security service does not authorize Workspace emails, invitation delivery or project actions. Invitation delivery uses its own explicit command and outbox above. Account UX is BUILD-complete for the supported flows; live delivery remains WIRE/VERIFY-pending. No provider credential or new external account is needed to continue independent development.

## Operational integration contract

Persist request/attempt/result identities and provenance in MIRIAM; never depend on replaying AI or provider memory. External writes still need exact action content, applicable human/resource authority, stale revalidation and an unknown-outcome recovery path before they can execute. Search retries can repeat a read/charge; Workspace Email and Calendar separate uncertain writes, proof-based reconciliation and bounded reads.

Secrets belong only in ignored local environment or deployed secret storage. Browser configuration endpoints return capability status only. Do not send the full Workspace to search or mail transport. Research filters unsafe result URLs and does not fetch them; a future page-fetch capability needs its own SSRF/redirect/content controls.
